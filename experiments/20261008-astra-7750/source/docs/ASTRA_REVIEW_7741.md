**New Medium: dangling anchor is not absence of its directory entry.** `_read_anchor()` still uses `open(self._id_path(path), "rb")` and catches FileNotFoundError (`:531`–`:534`) without checking the entry itself. No monkeypatched OS failure is needed.

This is a **pre-existing** hole exposed by this round's broadened strict-presence audit, not introduced by the new lstat helper. It violates the startup's documented read-only behavior for damaged artifacts and “new only when neither exists” rule (policy `:105`–`:111`; reducer `:630`–`:638`), and the new universal strict-entry claim (policy `:160`; README `:109`). The effect is silent loss of an existing recovery/identity entry and healthy admission of ambiguous storage, **not** replay of a discarded authorization. Require explicit error-propagating namespace inspection when anchor open reports ENOENT: only a genuinely absent anchor entry is first-use; an existing dangling/nonreadable entry must fence and remain untouched. Rerun regular/missing/dangling anchor controls and first-use/clearance matrices. The Medium artifact-preservation violation is the production-gate blocker; the Low audit-field omission alone would not establish a storage replay defect.
