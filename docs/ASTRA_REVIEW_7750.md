## 3. Strict reads, archive audit and remaining gaps

**Read-path claim confirmed with scope.** AST inspection finds zero builtin `open()` calls and zero error-suppressing existence predicates in reducer. `_read_regular()` is the only `os.read` site; `_verify_on_disk()` is the only `os.pread` site. The latter validates the opened descriptor's regular type and current anchor before hashing. `_open_journal()` reads exact active journal and `.id` names; reset-intent and legacy markers are lstat-only startup barriers. `_replay_journal()` operates on already parsed pending records, sequence/digest and in-memory state; it opens no file. Archive fields in reset records are metadata, not paths to dereference. Constructed archive paths only flow to exclusive write-only creation or rename. There is no archive glob/discovery. The behavioral trace plants valid former rebind bytes in archives plus archive symlinks, rejects any read-mode archive open, performs two held starts/full replays and verify, then explicit reissue/restart: **zero archive reads**. This is automatic startup/replay behavior, not a prohibition on an operator explicitly configuring an archive as the active journal.

**F-regular-check-after-blocking-open — OPEN Medium.** O_NOFOLLOW prevents a final-component symlink follow; it does not prevent opening a FIFO. `verify_journal()` does `os.open(..., O_RDONLY | O_NOFOLLOW)` at `:923`, and only later `_verify_on_disk()` fstat-checks at `:889`. Replace a healthy active journal with a FIFO with no writer and verification blocks in the open, rather than returning False with a `changed` fence. The independent process witness waits 0.5 s after entering the call, confirms it has not returned, opens the writer end, and only then observes completion; this is a real kernel FIFO handshake, not a mocked sleep or timing-only claim. Two more witnesses replace a regular journal/anchor with a FIFO **after lstat, before open** in `_read_regular()` (`:554`), also preventing the promised `unwritable` result until a writer appears. Existing-intent confirmation has the same open-before-fstat structure (`:494`); its corresponding FIFO race is a code-level concern, not counted as a fourth behavioral witness.

The runtime FIFO case does not require a writer racing a syscall: the malformed entry exists before verification begins. It can hang the service's verification/recovery path instead of failing closed observably. Steady-state FIFO startup is correctly rejected at lstat; the separate startup FIFO race requires concurrent namespace mutation. No unwanted rebind is applied by these fixtures. Use a nonblocking, no-follow descriptor open with strict regular-file validation (and preserve device/inode comparison where applicable), or an equivalent approach that cannot wait for a special-file peer before classification. Test runtime verify/append and strict-reader/intent swaps without leaving blocked workers. The blocking-open availability violation is the Medium gate blocker, not an authorization-resurrection claim.

**F-runtime-directory-swap-health — OPEN Low.** In the 15 nonblocking runtime type controls, final-component symlinks and anchor nonregular entries fence as expected. But a journal directory opened for append yields EISDIR at `:947` before `_verify_on_disk()` can reject its type. Only FileNotFoundError and ELOOP become `_JournalChanged`; generic OSError reaches `:1521`, logs refusal and leaves no fence. The public rebind result is truthfully refused/not applied/not durable, but status remains healthy. Policy `:178`–`:179` promises the nonregular runtime journal fences `changed`. Classify nonregular open failures consistently while retaining the existing distinction between integrity change and ordinary transient write refusal. Add the directory append case, not just verify and symlink cases.

**Ancestor and check/replace boundaries are not hardened.** `lstat()` and O_NOFOLLOW protect the final entry, not parent components. Five real fixtures with a symlink journal directory are accepted for startup, verify, append, clear and reset. `_fsync_dir()` (`:406`–`:411`) opens `dirname(abspath(path))` without O_DIRECTORY/O_NOFOLLOW or a pinned directory descriptor. Later path-based rename/unlink can therefore follow a retargeted ancestor. `_move_aside_if_not_regular()` has a lstat→rename window; first-use creation and clear/reset final replacements are not conditional on an unchanged namespace; runtime verification binds bytes to the opened descriptor, not the current pathname after open.

[Excluded-scope race evidence](../experiments/20261008-astra-7750/namespace-scope7750-final.json) demonstrates (1) inserting an anchor symlink after both absence checks allows first-use replacement, (2) changing a regular anchor to a symlink after clearance's lstat loses that new entry rather than archiving it, and (3) retargeting a parent symlink **after opening the commit descriptor**, with a matching header/pending pair at the new target, lets the detached directory receive the commit while the new target retains only pending. Live result says applied; replay through the new target is held. These require intentional concurrent namespace mutation and are **not** newly approved behavior or proof of protection by O_NOFOLLOW. One writer, protected stable ancestors, no retargeting and stopped-service recovery remain mandatory. A stable trusted directory symlink is supported; a symlink-free/pinned protected storage root is the clearest deployment condition. No universal race-proof or hostile-filesystem claim is made.

## 4. Retained integrity checks and accepted limitations

All **16 primary / eight focused journal groups** pass. **1,440 supersession schedules / 15,840 event-prefix checks** and **144 hold/rebind schedules / 1,152 checks** pass. Applicable 7638–7741 refusal, pending/commit failure, identity, legacy startup, content/order, permissions, artifact, restore and valid-prefix controls rerun through the retained composite harnesses. `recovery7708.restore_guidance` still records the obsolete clearance-only restore witness; the actual policy now requires pre-replay reset and the retained exact-reset test passes.

The requested architectural limitations are stated accurately in repository documentation:

- Unkeyed hashes are not a MAC; an authorized storage writer can recompute them (policy `:204`–`:208`).
- Joint journal/`.id` rollback can revive discarded decisions without successful reset **before any replay**; clearance on a healthy restored pair is a no-op (policy `:112`–`:131`; README `:100`–`:104`).
- Clean complete-record suffix truncation with matching identity is accepted at restart and can drop rebinds; a live whole-file verification can notice it (policy `:198`–`:206`; README `:100`–`:101`).
- Snapshot, partial and synthetic replay are unsupported: use the full original ordered stream (policy `:87`–`:89`, `:126`–`:127`).
- If intent cannot be confirmed durable, the original pair is unchanged before confirmation, but a visible partial marker may disappear on crash. Keep service stopped, repair permissions if relevant and retry reset before replay (policy `:180`–`:191`; README `:107`–`:108`).
- Nonregular journal/anchor entries require explicit clear/reset; nonregular intent markers require stopped-service cleanup/retry, while unreadable regular markers require permission repair (policy `:157`–`:159`, `:169`–`:191`).
- Linux/O_NOFOLLOW qualification is explicitly documented in **`docs/ASTRA_REVIEW_7741.md`**, findings and sections 2/4. Primary README/policy do not repeat the portability caveat. `getattr(os, "O_NOFOLLOW", 0)` is not equivalent protection when unavailable: the retained forced-zero control follows a same-inode symlink. This is Linux-only review qualification, not a claim that every non-Linux OS lacks the flag.

Both active files genuinely absent remains indistinguishable from first use. Archive strings are not authenticity proofs. Parent-directory symlinks and races have the bounded scope described above; storage permissions must protect ancestors, not just file bytes. Full ordered event retention, one writer and recovery before serving remain required. Synchronous verification is linear in journal size. Power-cut/firmware persistence, performance qualification and unavailable-O_NOFOLLOW platforms remain unapproved. These accepted limits do not excuse a stable runtime FIFO verification hang or the incorrect directory-swap health status.
